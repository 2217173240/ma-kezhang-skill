# 示例一：进度 / 数据类追问（S1）

## 输入情境

- 提问方：央国企客户的信息中心负责人
- 转述链路：客户 → 我方销售 B → B 的 AI 助手 → 本 skill
- 已知事实：功能已开发完成，正在灰度验证；公司没有对外承诺过具体上线日期；上周的周报里写的是"处于上线前验证阶段"
- 未知/无授权：具体上线日期
- 客户原话："你们上次说好的功能，怎么到现在还没上线？到底什么时候能用？"

## 分类

S1 进度 / 数据类。两个问题：进度（到哪一步）+ 时间（什么时候）。**不给数字，转过程；不给日期，转节点 + 渠道。**

## 输出

**正式版（邮件/纪要可用）**

> 关于功能上线节点，我们非常理解您的关注。该项目已完成主体开发，目前正在按既定流程进行灰度验证，重点核对数据一致性与异常处理逻辑，以确保交付质量。整体工作仍在按计划推进，未出现影响交付目标的变化。具体上线日期，我们会在验证结论确认后，通过正式渠道第一时间同步，避免双方口径不一致。请您放心，我们一直在积极推进。

**口头版（2 句）**

> 这功能主体已经做完了，现在在做上线前的灰度验证，为的就是别上线后出数据问题。具体日期我不给您一个不准的数，验证一有结论我第一时间告诉您。

**针对央国企客户的调整**

"按既定流程""正式渠道""口径不一致"这类词对央国企客户是加分的——它们暗示对方也在体制内，听得懂"口径"两个字的分量。可以额外提一句已纳入对方的项目管理例会议题，说明不是内部拖着。

## 用到的规则

- 三转：转过程（数字 → 阶段）、转渠道（日期 → 正式同步）
- 四不：不具体、不承诺
- 保留的真实锚点：主体开发完成、灰度验证、数据一致性核对、周报口径

## 自检

| # | 检查 | 结果 |
|---|---|---|
| 1 | 有无具体数字/日期/金额/人名 | 无 ✅ |
| 2 | 有无"一定/肯定" | 无 ✅ |
| 3 | 有无承认或否认 | 只承认"未出现影响交付目标的变化"——这是**能站住**的表述，且未否认风险 ✅ |
| 4 | 有无归因 | 无 ✅ |
| 5 | 有无渠道和下一步 | 有：验证结论确认后正式渠道同步 ✅ |
| 6 | 对方能否安全转述 | 可以，转述后不会被追问出细节 ✅ |

## 注意

如果客户第二次追问"我不问日期，你告诉我风险大不大"，不要答"没风险"——切到 S3，用"已识别项已纳入验证清单，风险总体可控，具体情况以验证报告为准"。

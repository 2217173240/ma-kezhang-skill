# 马科长 skill

一个把"答非所问"变成可复用规则的 agent skill：**当问题必须回应，但答案不能给全的时候，怎么说得得体、留有余地，还让对方拿得出手。**

它的原型是 2011 年那段著名的央视采访。武安市发改局工业科科长马禄昌面对"钢铁产能到底多少"的追问，全程只背产业历史和政策口径，中间沉默了七八秒，最后小声说"别讲了，说不出来"。当年他被全网嘲笑，后来口碑反转——武安靠钢铁吃饭，数万人的生计压在他一个人身上，他既不能说谎，又不能让一句话变成后续追责的凭据。**他不是不会说，是不能说。**

这套 skill 把那种处境里的应对方式，抽成了可以照着写的规则。今天最常见的使用场景是转述链路：A 让 AI 起草内容，发给 B，B 又转给自己那边的 AI，最后落到客户面前——中间任何一手，都不希望自己被那句话装进去。

---

## 为什么值得用

**核心逻辑只有两句：用"过程"代替"结果"，用"态度"代替"信息"。** 在沟通环境不确定、口径没定、授权不足的时候，它给用户垫一层安全缓冲——话说了，姿态到了，但没有替任何人下一句结论。

它处理的其实是 AI 在真实人际沟通里的一个特殊位置：**做一个"社会性角色"，而不只是一个"任务执行者"**。眼下大多数 skill 都在解决"如何把事情做对"——更准、更快、更少跑偏；这个 skill 解决的是另一半——**如何把事情说得让人挑不出错**。

这类需求在 To B 场景里尤其密集。政企、央国企、大客户的沟通里，答案常常不缺，缺的是"这句话谁来说、说到什么程度、留不留痕"。尤其在 A→AI→B→AI→客户的转述链路上，每一手都要求自己不被前一手装进去、也不被后一手反打。这就是它的应用空间。

---

## 它做什么，不做什么

**做**：把具体问题转成过程、程序、渠道。不编数据、不承诺、不否认事实、不归因个人。

**不做**：不帮你编数字、瞒重大风险、骗监管审计、逃合同义务。判断标准只有一条——**这段话如果被原封不动拿到监管、审计、法庭或合同对方面前，站不站得住。** 站不住就不写。

对外缓冲也不等于对内失真：内部记录必须如实，"延期两周"要照写，缓冲只处理对外措辞。

---

## 总原则：三转、四不、一留

**三转**

1. **转过程**：不问结果，答推进阶段。
2. **转程序**：不问谁拍板，答按流程研究。
3. **转渠道**：不当场给准话，答以正式材料为准。

**四不**：不具体（不给数字、日期、金额、人名）、不承诺（不说"肯定行"）、不否定（不说"不可能"）、不归因（不甩锅个人、部门、政策、客户）。

**一留**：留正式渠道——书面、会议纪要、正式通报、专人对接。

**输出骨架**：共情 → 过程 → 原则 → 渠道 → 下一步。默认给两版，正式版用于邮件/纪要，口头版两三句，当面能自然说出口。

## 四类场景

| 场景 | 典型问法 | 策略内核 | 展开 |
|---|---|---|---|
| **进度 / 数据** | 到哪一步了？为什么还没上线？完成率多少？ | 数字问题 → 过程问题；时间问题 → 节点问题 | [scenarios.md](references/scenarios.md) · [progress.md](examples/progress.md) |
| **敏感决策 / 责任** | 谁拍板的？为什么选这家？出了问题谁负责？ | 个人决策 → 组织程序；程序化、集体化、留痕化 | [scenarios.md](references/scenarios.md) · [responsibility.md](examples/responsibility.md) |
| **具体困难 / 风险** | 为什么延期？是不是超支？会不会烂尾？被通报了吗？ | 宏观叙事 + 普遍性 + 总体可控 + 已纳入体系 | [scenarios.md](references/scenarios.md) · [risk.md](examples/risk.md) |
| **无法回避的终极追问** | 别绕了，行还是不行？给个准话。 | 承认重要 + 需要核实 + 当场不拍板 + 书面答复 | [scenarios.md](references/scenarios.md) · [pressure.md](examples/pressure.md) |

每类在 [references/scenarios.md](references/scenarios.md) 里都按同一结构展开：典型问题 → 风险 → 核心策略 → 话术零件 → 完整示例 → 红线。真实对话常常混着来（先问进度、再追责任；先问风险、再施压要准话），文末给了组合处理顺序和一条升级信号：一旦对方说"我要书面答复""我会走正式函件"，立即停止口头缓冲，转材料准备和授权回复。

下面是四类场景的完整问答示例，可以直接照着结构改写。

### 场景一：进度 / 数据类追问

> **对方**：你们上个月承诺的功能为什么还没上线？
>
> **缓冲回复**：关于功能上线节点，我们非常理解您的关注。目前研发团队正根据测试情况对部分细节做最后优化和验证，以确保交付质量，整体工作仍在按计划推进。具体上线日期，我们会在确认后通过正式渠道第一时间同步，避免口径不一致。请您放心，我们一直在积极推进。

策略是数字问题转过程问题、时间问题转节点问题：不编具体日期，不说"下周一定"，也不把延期原因推给某个人。

### 场景二：敏感决策 / 责任类追问

> **对方**：这个项目是不是你们领导拍板的？
>
> **缓冲回复**：项目决策严格遵循相关制度和审批程序，经过了必要的论证和研究，不是个人能决定的。具体决策记录可以通过正式渠道了解。我们当前的重点是按既定方案推进，确保后续交付。

策略是把个人决策转成组织程序：不甩锅具体个人，不承认也不否认违规，不透露未公开的决策过程。

### 场景三：具体困难 / 风险类追问

> **对方**：听说你们资金链紧张，会不会影响交付？
>
> **缓冲回复**：我们理解您对交付的关切。当前外部环境确实带来一定挑战，公司已统筹资金和资源，项目正按既定安排推进，风险总体可控。具体安排我们会通过正式渠道同步，请您放心。

策略是宏观叙事加"总体可控、已纳入体系"：不轻率说"完全没问题"，不泄露财务细节，不把风险推给客户或政策。

### 场景四：无法回避的终极追问

> **对方**：你就说能不能按期交付？
>
> **缓冲回复**：我理解您需要明确答复。按期交付是我们共同目标，目前团队正按计划推进。但最终日期我需要根据最新节点确认后，通过正式渠道给您准确答复，避免口径不一致。确认后我第一时间同步。

策略是承认问题重要、需要核实、当场不拍板、留书面答复：不硬刚"无可奉告"，不编造，不承诺超出权限的事。这一场如果发生在会议现场，先给口头版稳住场面，会后补一份书面说明。

### 多轮追问怎么接

真实场合很少一问一答就结束。以下是三组常见的升级节奏。

#### 第一场：从进度追问到责任归属（S1 → S2）

> **对方**：项目现在到哪一步了？
>
> **缓冲回复**：目前已完成主体开发，正在按既定流程进行验证，关键环节基本走完，整体仍按计划推进。
>
> **对方**：那你给我个准确日期，我明天要向上汇报。
>
> **缓冲回复**：理解您要向上说明，最怕的就是口径打架。具体日期我需要按最新节点核实后再给您，今天下班前形成一份简短说明发您，您照着汇报不会出错。
>
> **对方**：是不是你们内部返工了？我听说存在这个问题。
>
> **缓冲回复**：您提到的这个情况我需要核实准确口径，不便凭听说下判断。验证阶段的结论会完整体现在书面材料里，有需要调整的地方我们会一并说明。
>
> **对方**：到底谁定的这个时间点？出了事谁负责？
>
> **缓冲回复**：时间节点是经过内部评审和集体研究形成的，不是个人能定的。具体决策记录可以通过正式渠道了解，我这边负责把项目推进好。

要留意的是第三轮的转向：对方从"问事实"转成了"要你评价事实"。这一步不要接评价，只说"需要核实口径"。责任问题一旦落到具体个人，你就被绑上了决策链。

#### 第二场：从风险拷问到"行还是不行"（S3 → S4）

> **对方**：我听说你们这个项目成本超了不少，是不是真的？
>
> **缓冲回复**：我们理解您对成本和交付的关切。项目推进中确实面临一些阶段性挑战，公司已统筹资源并建立专项机制跟踪，整体仍在可控范围内。具体成本口径以正式财务和项目材料为准。
>
> **对方**：那到底还能不能按期交付？你们别到时候烂尾了。
>
> **缓冲回复**：按期交付是我们共同的目标，团队一直在按既定安排推进，相关事项已纳入风险管控体系统筹考虑。如有影响交付的确定变化，我们会第一时间正式告知贵方，不会让您被动。
>
> **对方**：你就给我个准话，能不能按期？
>
> **缓冲回复**：您这个问题很关键，我不能随口应您。我需要根据最新节点核实后，今天下班前给您书面答复，绝不让您在排期上被动。

这里最容易失守的是第三轮。前面已经说了两轮"总体可控"，对方一逼，很容易顺手补一句"能按期"——那就等于替公司下了结论。**"总体可控"说的是能力和意愿，"能按期"说的是结果，两者不能混。** 用"书面答复"把结论性的判断留在授权范围内。

#### 第三场：对方就要一个数字（S1 → 施压）

> **对方**：别跟我说过程，完成率到底多少？
>
> **缓冲回复**：具体数字我按正式口径给您，避免我说一个、正式文件写一个。目前主体工作已基本完成，剩余部分在验证收尾，这个判断是准确的。
>
> **对方**：你现在就报一个数给我，我记一下。
>
> **缓冲回复**：口头报数最容易出偏差，给您写错的数反而更耽误事。这个数我向项目组取准确口径，今天下班前书面发您。
>
> **对方**：你是不知道，还是不想说？
>
> **缓冲回复**：不是不想说，是不想给您一个不准的数。您要的这份数据我按归口渠道取，取到就发您，不用您再催第二遍。

二选一式的逼问（"不知道还是不想说"）是常见的破防点。不要接这个二选一，也不要解释自己的难处，回到**动作**上：什么时候给你、通过什么渠道给你。态度上完全配合，事实上一点不松——这两件事并不矛盾。

### 什么时候停止缓冲

一旦对方说"我要书面答复""我会走正式函件""我向上反映""让法务对接"，立刻停止口头缓冲，转材料准备流程：确认口径、准备材料、走审批、由授权人正式回复。继续用话术应对正式程序，会从"谨慎"变成"阻挠"。

## 两张工具表

**替换词表**（[references/lexicon.md](references/lexicon.md)）：不知道 → 需要核实准确口径；没做 → 正在按计划推进；延期 → 动态优化节点；有问题 → 面临阶段性挑战；领导决定的 → 经过既定程序研究；肯定行 → 在条件具备的情况下全力推进；被通报了 → 相关情况以正式通报为准。注意别堆叠，一段话用两三个就够，并且至少留一个真实可查的锚点（已完成的环节、正式材料名称、责任部门），否则整段话既没信息量也不可信。

**自检六问**（[references/self-check.md](references/self-check.md)），交付前逐条过：

1. 有没有具体数字、日期、金额、人名？
2. 有没有承诺"一定、肯定、必须"？
3. 有没有直接否定或承认某个事实？
4. 有没有把责任归到具体个人或部门？
5. 有没有留正式渠道和下一步动作？
6. **对方能不能拿这段话去向上汇报，而不把你装进去？**

第 6 问是整套方法的落点。缓冲的质量不取决于你说得多圆，而取决于**对方能不能安全地转述你**：转述之后他不会被追问住，你也不会被那段话反打。当年那位科长之所以成为名场面，恰恰是因为他连一句可被引用的话都没留下。

唯一允许出现具体时间的情形，是承诺**你自己的动作**——"今天下班前给您书面答复"，而不是承诺业务结果。

## 怎么用

1. 把整个目录放进你 agent 的 skills 目录，`SKILL.md` 的 frontmatter（`name` + `description`）就是识别入口。
2. 想直接抄，去 [examples/](examples/) 找最接近的一篇，照结构改写；每篇都附了情境、输出、用到的规则和自检打分。
3. 遇到"到底行不行"的僵局，走 [examples/pressure.md](examples/pressure.md)：承认问题关键、说明为什么不当场拍板、给出你自己可控的下一步。
4. 动手前先看 [SKILL.md](SKILL.md) 的硬边界那一段。

```text
ma-kezhang-skill/
├── SKILL.md                  # 主入口：适用信号、硬边界、五步流程、输出示例
├── README.md                 # 本文件
├── references/
│   ├── scenarios.md          # 四场景完整展开 + 组合使用 + 升级信号
│   ├── lexicon.md            # 替换词表
│   └── self-check.md         # 自检六问 + 不合格案例对照
└── examples/
    ├── progress.md           # S1 进度 / 数据
    ├── responsibility.md     # S2 决策 / 责任
    ├── risk.md               # S3 困难 / 风险
    └── pressure.md           # S4 终极追问
```

它省掉的是尴尬和口径风险，不是事实和责任。做的也不是"如何把事情做对"，而是"如何把事情说得让人挑不出错"。
